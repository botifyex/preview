# Решения

Коротко: что выбрали, с чем сравнивали и почему.

| Вопрос | Выбрали | Отвергли | Почему |
| --- | --- | --- | --- |
| Запуск скриптов | Тонкий файл-вход `run_*` с зависимостями PEP 723 через `uv run` и пакет рядом с ним (`run_capture.py` и `capture/`, `run_resolve_range.py` и `resolve_range/`). Файл поставляется только вместе со своей папкой | Один файл на скрипт; пакет с установкой; shell; вход с именем пакета (`capture.py` рядом с `capture/`); вход внутри пакета | Нет шага установки, версии зафиксированы рядом с кодом. Для PEP 723 нужен файл вне пакета: запуск файла внутри него кладёт в `sys.path` папку пакета, а не её родителя, замер даёт `No module named 'capture'`. Вход с именем пакета отвергнут: два одинаковых имени рядом путают. От одного файла отказались: скрипт захвата перерос 900 строк (933) и стал перегружен. Shell не вытянет браузер и разбор версий |
| Браузер | Playwright, версия закреплена (1.64.1) | Puppeteer; Selenium | Единый API локаторов по роли и тексту, сохранение сессии, готовый Chromium. Закреплённая версия берёт нужную сборку браузера из кэша |
| Рисование пометок | SVG в странице, координаты из браузера | Рисовать на готовом PNG; просить модель указать места | Геометрия берётся из настоящей страницы, поэтому нарисовать мимо элемента нельзя; текст измеряется самим браузером |
| Промах локатора | Падение с именем локатора; локатор обязан найти ровно один элемент | Рисовать по приблизительным координатам; брать первый найденный | Лучше нет картинки, чем картинка, которая врёт |
| Частичный сбой | Всё или ничего: файлы появляются только при полном успехе | Оставлять готовые кадры | Иначе нумерация и манифест расходятся с тем, что на диске |
| Порядок версий | По номеру версии | По дате тега | Поздний бэкпорт `1.9.1` не должен становиться «последним релизом» после `1.10.0` |
| Схемы версий | SemVer и PEP 440 в одном разборе | Только SemVer | Проекты на Python ставят теги вида `1.2.0b1`; остальные теги считаем не версиями и игнорируем |
| Считается ли rc бетой | Да: канал беты это beta и rc. Alpha нет | Только beta; все предрелизы | rc получают те же тестировщики, что и бету. Alpha обычно внутренняя, граница по ней дала бы пустой или неверный отрезок |
| Стабильный релиз новее последней беты | Начало отрезка сдвигается на этот релиз (с записью в `notes`); если HEAD и есть этот релиз, показываем отрезок от последней беты до него | Всегда от последней беты | Всё до релиза уже вышло, и рассказывать об этом как о новом в бете неверно |
| Первая версия без предыдущей | Ошибка с подсказкой про `--from` | Вся история | Вся история проекта почти никогда не то, что хотели; пользователь выбирает начало сам |
| Удалённое на странице | По порядку: старая версия через `before_url`, маркер `removed` от соседа со смещением, только текст | Маркер без опоры; утверждать по коммиту | Элемента больше нет, опереться можно только на то, что есть. Без проверки ничего не утверждаем |
| «Было» отдельным номером | Кадр `before` получает свой номер перед текущим | Подномера вида `3a`; склейка в один файл | Сквозная нумерация остаётся простой, и на каждый кадр можно сослаться |
| Ссылка на картинку в тексте | Обычная ссылка Markdown на файл | Текст вида «рис. 1» | Не зависит от языка, проверяется машиной и кликается |
| Разделы отчёта | Проверяются по положению: `#`, затем два `##` | Фиксированные названия; скрытые маркеры | Заголовки пишутся на языке пользователей, а скрытые маркеры легко потерять |
| Где хранится сессия | `~/.cache/preview/state`, внутри свой `.gitignore`, файлы с правами 600 | `.preview/state` в проекте | Настоящий запуск показал, что запись в чужой репозиторий лишняя; вне проекта сессия не попадёт в git |
| Чья это сессия | Файл с хешем от адреса, блока входа и значений его `value_env` | Только `login.name` | Смена пользователя при том же имени молча давала снимки чужой учётной записи |
| Жива ли сессия | Перед каждым кадром со входом открываем страницу после входа и проверяем `expect`, иначе входим снова | Верить наличию файла | Выход из системы в шаге кадра давал снимок формы входа без ошибки. Цена: одна лишняя загрузка на кадр |
| Сохранение спецификации | `figures/spec.json` как есть; литеральный пароль в поле пароля это ошибка | Вырезать значения при сохранении | Вырезанная спецификация не повторяется. Проверяется настоящий `type` поля, а не догадка по имени |
| Запрет продакшена | В заметке и ещё раз в пакете `capture` | Только текст в SKILL.md | Жёсткая проверка срабатывает, даже если агент ошибся |
| Автозапуск навыка | `disable-model-invocation: true`, только явный вызов | Автоматический выбор моделью | Навык запускает стек и создаёт пользователей; это должно быть осознанное действие |
| Форма поставки | Папка навыка плюс манифест плагина; установка ссылкой или через `--plugin-dir` | Только плагин; копирование файлов | Манифест необязателен и не мешает, ссылка позволяет править исходник на месте |
| Название | `preview`, вызов `/preview <access\|release\|beta>`; бывшее имя release-preview | Оставить старое | Выбор владельца: короче, а режим `release` остаётся режимом |
| Тесты | pytest через `uv run`, настоящий git и Chromium, скрипты запускаются как у пользователя. `pyproject.toml` с `package = false` хранит настройки инструментов и закреплённые зависимости для разработки | Моки; `uv run --no-project --with` без закреплённых версий | Проверяется реальное поведение через CLI. Собранного пакета по-прежнему нет: `--help` каждого скрипта из корня, из `/` и из чужого проекта совпал с прежним, `.venv` в чужой папке не появился |
| Проверка кода | ruff и basedpyright, версии закреплены; режим basedpyright `recommended` без `reportAny`, `reportExplicitAny`, `reportUnusedCallResult`, `reportImplicitStringConcatenation` | Режим `strict`; `recommended` без отключений | `recommended` строже `strict`: к ошибкам он добавляет 458 предупреждений. Из них 342 это `reportAny` и `reportExplicitAny`: `Spec = dict[str, Any]` сделан намеренно, спецификация это недоверенный JSON с проверкой во время выполнения. Ещё 92 это `reportUnusedCallResult`: просмотр всех мест не нашёл потерянного результата, важного для логики |
| Права файлов сессии | Каталог 700, файлы создаём через `os.open(..., 0o600)` до записи; файлы прошлого запуска сужаем до перезаписи. Нечитаемый файл сессии значит новый вход | `chmod` после записи | Между записью и `chmod` токены были доступны всем. Playwright пишет через `open(path, "w")`, права существующего файла сохраняются: проверено тестом. Существующий каталог не трогаем: его мог указать пользователь |
| Публикация кадров | Всё или ничего: записи в staging, новое и старое через служебный каталог внутри `figures`, при ошибке обратный порядок. Если откат не удался, каталог остаётся и называется в ошибке | Удалить и затем копировать | Ошибка посреди публикации оставляла каталог без старых кадров и без манифеста. Служебный каталог внутри `figures` лежит на той же файловой системе и при ссылке, и при точке монтирования, поэтому замена остаётся переименованием |
| Что считается своим файлом | Только базовые имена из существующего `manifest.json`, подходящие под шаблон кадра, плюс `manifest.json` и `spec.json`. Плохой манифест значит, что своих кадров нет. Чужой файл на месте нового кадра это отказ, до запуска браузера и ещё раз при публикации | Любой файл по шаблону имени | Инструмент молча удалял и перезаписывал чужие файлы. Записи манифеста с `..` не выводят наружу: берётся только имя |
| Проверка спецификации | Типы всех полей проверяются до запуска браузера, числа ограничены 1000000000, ошибка это `error: ...` и код 1 | Общий `except Exception` | Общий перехват прячет ошибки в самом инструменте. Ошибки Playwright вне кадра ловятся отдельно, конкретным типом |
| Проверка окна для `full_page: false` | После рисования проверяем всё нарисованное: опоры, рамку, стрелку, номер с радиусом и подпись; подпись браузер возвращает сам. Рамка, хвост стрелки по умолчанию, подпись и номер `corner` или `top-left` прижимаются к видимой области, явное `offset`, `from` и другие размещения вне её это отказ | Только опора; расчёт подписи в Python | Часть пометки могла быть обрезана снимком без ошибки. Ширину текста знает только браузер |
| Цвет пометок | Поле `color` на аннотации, кадре и спецификации, ближайший побеждает; по умолчанию `#E6004C`, значение приходит в `DRAW_SCRIPT` с каждой пометкой. У `removed` свой `#C81E1E`, меняет его только `color` на самой пометке | Цвет в JS; цвет кадра или спецификации и для `removed` | Настройка в одном месте `resolve_color` подойдёт новым видам пометок. Удаление должно отличаться от добавления. Белый текст на `#E6004C` даёт контраст 4,70:1, выше порога AA 4,5:1 |
| Новые фигуры пометок | `callout`, `ellipse`, `underline`, `highlight`, `spotlight`, `connector`. Текст `callout` переносит и измеряет браузер, строки и место считает Python, сторона без места это отказ. Эллипс проходит через углы рамки в 4 px. `spotlight` и `highlight` рисуются под остальными пометками, их прозрачность постоянна | `foreignObject` с HTML; эллипс, вписанный в рамку; настраиваемая прозрачность; угадывать другую сторону при явном `side` | Со строками в манифесте видно, что нарисовано, а HTML внутри SVG наследовал бы CSS страницы и менял перенос. Вписанный эллипс пересекает углы длинного элемента и текст в них. Настройка прозрачности не решает никакой задачи: числа 0,25 и 0,6 проверены на светлой, тёмной и плотной страницах |
| Составные изображения (схемы) | Фигура с `panels` даёт один нумерованный PNG; Python считает раскладку и маршруты чистыми функциями по измеренным размерам, рисует одна страница Chromium (картинки и SVG). Стрелка, которую нельзя провести мимо панелей, это отказ | Отдельный номер на каждую панель; Pillow; отдельный инструмент после съёмки | Один PNG оставляет без изменений нумерацию, манифест, публикацию всё-или-ничего и `check_report`. Браузер уже есть и рисует теми же шрифтами и пометками, Pillow стал бы новой зависимостью и вторым рисовальщиком. Отдельный инструмент потерял бы координаты пометок и публикацию всё-или-ничего |
| Витрина `examples/showcase` | Свой вымышленный статический сайт в репозитории, кадры и манифест собирает `build.py`, тест требует каждый вид пометки и каждую раскладку | Снимать внешний сайт; рисовать картинки вручную | Снимок внешнего сайта нельзя пересобрать, а его адреса и пути не стоит публиковать. Сгенерированные кадры нельзя подделать: тест пересобирает их и сравнивает манифест, а новый вид пометки без примера роняет тест |
